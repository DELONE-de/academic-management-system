PHASE 1 — AUTHENTICATION HARDENING

Objective

Move authentication away from browser-accessible JWT storage and establish secure cookie-based authentication.

Audit the current authentication implementation first.

Implement:

- HttpOnly authentication cookies
- Secure cookies in production
- SameSite protection appropriate to the existing deployment architecture
- Proper cookie expiration
- Logout that invalidates/removes the cookie
- Existing JWT authentication behavior preserved
- Backend authentication middleware updated to read the secure cookie
- Remove frontend dependency on localStorage for authentication tokens
- Remove unnecessary token exposure to JavaScript
- Ensure refresh/session behavior is consistent with the existing architecture

Do NOT redesign authentication completely.

Do NOT add OAuth/social login.

Do NOT add unrelated authentication features.

Test:

- login
- authenticated requests
- logout
- expired authentication
- invalid authentication
- protected routes
- role authorization
- browser/API behavior

PHASE 2 — CSRF PROTECTION

Because authentication is moving to cookies, implement appropriate CSRF protection.

First inspect whether the existing API is same-origin or cross-origin and determine the least invasive correct approach.

Implement:

- CSRF protection for state-changing requests
- POST
- PUT
- PATCH
- DELETE
- appropriate exemption for safe methods
- correct frontend API integration
- clear failure responses
- tests for valid and invalid CSRF requests

Do not introduce unnecessary infrastructure.

Ensure file uploads and SSE continue working.

Verify that authentication + CSRF work together.

PHASE 3 — APPROVAL / PUBLICATION ARCHITECTURE VERIFICATION

Audit the complete academic lifecycle:

"UPLOAD → EXTRACTION → VALIDATION → PROPOSED RESULT → REVIEW → APPROVAL → PUBLICATION → GPA/CGPA"

Verify that:

- AI-extracted data cannot silently become official
- deterministic calculations remain authoritative
- proposed results remain distinguishable from official results
- review items are properly linked
- approval hierarchy is enforced
- duplicate approvals are prevented
- unauthorized users cannot approve records outside their scope
- published records cannot be modified without the intended workflow
- GPA calculations use only the correct official/published data
- audit logs capture important state transitions
- department/faculty/role scoping is enforced throughout

Fix any architectural or security problems found.

Add regression tests for the entire lifecycle.

Do not redesign the workflow unless necessary to fix a real integrity/security problem.
